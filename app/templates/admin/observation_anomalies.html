Observation anomalies

Measurements in Best Practice whose value isn't a plain number. BP doesn't check height, weight, head circumference, BMI or blood pressure when they're entered, so a value like 72kg is stored as typed. Any query that reads it as a number then fails for that patient, including the one that loads their identifiers for redaction, which blocks their cloud AI pipelines until the value is corrected in BP. Values are shown between the shaded edges exactly as stored, so stray spaces are visible. Blood pressure is entered as one field but stored as two rows, systolic and diastolic. Observations filed under the wrong code

Rows whose name isn't Best Practice's own name for their code: a pulse filed as diastolic, a heart rhythm filed as weight. Nearly all were created by an import of another practice's records (created by user 0, one batch per patient). Anything that reads observations by code, {{ app_name }} included, takes them for the measurement the code means. Deleting one in BP (record status 3) removes it from {{ app_name }} at once, and from this list.
