Scribe Setup


        

            
Speaker diarization — "LLM Diarize transcript"

            
Each audio chunk is transcribed by the ASR model, then passed to an LLM that
               adds speaker labels ([Doctor] / [Patient])
               before the text reaches the Transcript tab.

            
The LLM step looks up a User Prompt with the exact name:

            
LLM Diarize transcript

            
    
                
  • Create this prompt in Admin → Prompt Manager → User Prompts.
    • 
                
  • Bind a system prompt containing the full diarization instructions.
    • 
                
  • Use {{ '{{input.raw_transcript}}' }} in the prompt text to inject the chunk.
    • 
                
  • Assign a default inference model on the prompt.
    • 
            

            
If the prompt is absent the raw ASR text is used without speaker labels.
               The prompt's model must be local: this step sends the
               transcript as it was heard, without redaction, so a cloud model is refused and
               the chunk is used without labels.

            
Deepgram speaker turns: on a Deepgram ASR model, set
               Speaker turns in Setup → AI Providers. Deepgram then splits each chunk
               into turns ([Speaker 1] / [Speaker 2], numbered
               afresh in every chunk) and the LLM step above is skipped, so no local model is
               needed. The line under ASR Model shows which way the chosen model
               works.

               Pipeline selector here.

                    anywhere in the pipeline name, e.g.
                    Consultation Note [SCRIBE].
    • 
                
  • Set the pipeline status to Active.
    • 
                
  • The pipeline receives the full transcript via {{ '{{input.raw_transcript}}' }}.
